# 워드프레스 초기 세팅 체크리스트

**위에서부터 순서대로** 진행하세요. 순서가 중요합니다 (예: 퍼머링크를 나중에 바꾸면 SEO 주소가 전부 깨집니다).

---

## 0단계 · 로컬 환경 (실서버 건드리기 전)

- [ ] [LocalWP](https://localwp.com) 설치 (무료)
- [ ] 새 사이트 생성: 이름 `caparol`, PHP 8.x, MySQL
- [ ] 여기서 전부 만들고, 완성된 뒤에 실서버로 옮깁니다

> 처음부터 실서버에서 만들면 미완성 페이지가 검색엔진에 색인되고, 실수하면 되돌릴 수 없습니다.

## 1단계 · 기본 설정 (테마 고르기 전에)

- [ ] **설정 → 일반**: 사이트 제목 `카파롤 코리아`, 태그라인 작성 (기본값 "또 하나의 워드프레스 사이트" 반드시 변경)
- [ ] **설정 → 고유주소**: **글 이름**(`/%postname%/`) 선택 ← 가장 먼저
- [ ] **설정 → 토론**: 댓글 전체 비활성화 (스팸의 90%가 여기로 들어옵니다)
- [ ] **설정 → 미디어**: 이미지 크기 정리, "월/일 기준 폴더 정리" 체크
- [ ] **설정 → 읽기**: 구축 중에는 "검색 엔진 노출 방지" **체크** → 오픈 시 해제 (⚠️ 해제 잊으면 검색에 영원히 안 나옵니다)
- [ ] 언어: 한국어, 시간대: 서울

## 2단계 · 테마 — Astra

- [ ] **Astra** 설치·활성화 (모양 → 테마 → 새로 추가 → `Astra` 검색)
- [ ] 이 저장소의 `theme/caparol-child/` 를 `wp-content/themes/` 에 복사 후 **활성화**
      (`style.css`·`functions.php` 는 Astra 자식 테마로 이미 맞춰져 있습니다)
- [ ] 기본 테마(Twenty*) 하나만 남기고 나머지 삭제 (안 쓰는 테마 = 보안 구멍)
- [ ] **모양 → 사용자 정의하기**에서 컨테이너 폭을 `1200px` 로 (ia.md의 `--caparol-max`와 일치)

> 부모 테마 Astra는 **절대 직접 수정하지 마세요.** 업데이트 때 전부 사라집니다.
> 모든 커스터마이징은 `caparol-child` 안에서 합니다.

## 2-b단계 · 페이지 빌더 — Elementor

- [ ] **Elementor** (무료) 설치
- [ ] **Elementor Pro** 설치 — **필수입니다.** 아래 이유 참고
- [ ] 블록 에디터와 **섞지 말 것** — 페이지마다 편집 방법이 달라지면 직원이 못 씁니다
- [ ] Elementor **사이트 설정 → 전역 색상**에 브랜드 컬러 등록
      | 이름 | 값 | 쓰는 곳 |
      |---|---|---|
      | Primary | `#96c11c` | 버튼·강조 배경 |
      | Secondary | `#5f7c0b` | 흰 배경 위 글씨·링크 |
      | Text | `#1a1a1a` | 본문 |
      | Accent | `#f4f8e6` | 옅은 배경면 |

### ⚠️ Atomic 편집기는 끄고 시작하세요

**Elementor → 설정 → `Atomic 편집기` 탭 → `비활성화`**

새 실험 편집기입니다. 켜져 있으면 **편집기에서는 정상으로 보이는데 실제 사이트에는
스타일이 전혀 적용되지 않습니다.** 색상까지 무시되며, 캐시·표시조건 문제로 오인하기 쉬워
원인 파악에 오래 걸립니다. 실제로 이 프로젝트에서 헤더 작업이 여기서 막혔습니다.

컨테이너 선택 시 패널 탭이 `레이아웃 / 스타일 / 고급` 이면 정상,
`일반 / 스타일 / 상호작용` 이면 Atomic입니다.

### ⚠️ Elementor Pro가 왜 필수인가

무료판으로는 **커스텀 포스트 타입 템플릿을 만들 수 없습니다.**

제품이 30개, 100개가 되어도 상세 페이지 **디자인은 하나**여야 합니다.
Pro의 **테마 빌더(Theme Builder)** 로 `제품 상세` 템플릿을 한 번 만들면
모든 제품에 자동 적용되고, 직원은 내용만 채우면 됩니다.

무료판으로 하면 제품마다 페이지를 손으로 만들어야 하고,
나중에 디자인을 바꿀 때 **100개를 하나씩 고쳐야 합니다.** 현실적으로 불가능합니다.

메가메뉴 위젯도 Pro에 들어 있어서, Pro 하나로 두 가지가 해결됩니다.

> 연 단위 구독입니다. 가격은 변동되니 [elementor.com](https://elementor.com/pricing/) 에서
> 현재 요금을 확인하세요. 사이트 1개짜리 가장 낮은 플랜이면 충분합니다.

## 3단계 · 플러그인 (10개 이하 유지)

플러그인 수 = 보안 위험 + 속도 저하입니다. 아래가 최소 구성입니다.

| 용도 | 플러그인 | 필수 |
|---|---|---|
| 페이지 빌더 | **Elementor** + **Elementor Pro** | ✓ |
| 제품 스펙 필드 | **ACF (Advanced Custom Fields)** | ✓ |
| SEO | **Rank Math SEO** | ✓ |
| 보안 (방화벽) | **NinjaFirewall (WP Edition)** | ✓ |
| 2단계 인증 | **Two Factor** | ✓ |
| 백업 | **UpdraftPlus** | ✓ |
| 캐시/속도 | **WP Super Cache** 또는 LiteSpeed Cache(서버가 LiteSpeed면) | ✓ |
| 이미지 WebP 변환 | **Converter for Media** | ✓ |
| 문의 폼 | **Contact Form 7** + Flamingo(접수 보관) | ✓ |
| 한국형 게시판 | **KBoard** | 필요 시 |
| 메가메뉴 | — | **불필요** (Elementor Pro에 포함) |
| 로그인 주소 변경 | **WPS Hide Login** | ✓ |

> 커스텀 포스트 타입은 플러그인(CPT UI) 대신 **`mu-plugins/caparol-core`** 코드로 등록합니다.
> 플러그인이 실수로 꺼지면 제품이 전부 사라져 보이고, 설정이 DB에만 남아 버전관리가 안 되기 때문입니다.
> 자세한 이유는 [mu-plugins/README.md](../mu-plugins/README.md) 참고.

**설치하지 말 것**: 방문자 카운터, 슬라이더 전용 플러그인(테마 기능으로 충분), 올인원 마케팅 번들, 출처 불명 한글 플러그인

### ⚠️ 보안 플러그인은 겹치면 오히려 위험합니다

"보안은 많을수록 좋다"가 통하지 않는 영역입니다. 기능이 겹치는 보안 플러그인을
여러 개 켜면 아래 문제가 생깁니다.

1. **서로 충돌해 관리자가 로그인에서 잠깁니다.** 특히 2단계 인증 플러그인이 둘이면
   실제로 자주 일어나는 사고입니다. FTP로 플러그인 폴더 이름을 바꿔야 겨우 들어갑니다
2. **어느 플러그인이 무엇을 막았는지 진단이 안 됩니다.** 문의 폼이 안 되거나
   특정 사용자가 못 들어올 때 원인을 못 찾습니다
3. **플러그인 자체가 공격면입니다.** 보안 플러그인에서도 취약점이 나옵니다.
   개수가 늘수록 위험도 늘어납니다
4. 매 요청마다 검사가 중복 실행되어 **사이트가 느려집니다**

기능별로 **하나씩만** 두세요.

| 기능 | 하나만 |
|---|---|
| 웹 방화벽 · 로그인 시도 제한 · 악성코드 스캔 | NinjaFirewall |
| 2단계 인증 | Two Factor |
| XML-RPC 차단 | `mu-plugins/caparol-core/inc/security.php` (코드로 처리 완료) |

> Login Lockdown(로그인 시도 제한), Really Simple Security(2FA·로그인보호),
> Disable XML-RPC-API 같은 것은 위 셋과 기능이 겹칩니다. **삭제하세요.**
> 비활성화만으로는 부족합니다 — 파일이 서버에 남아 취약점 공격 경로가 됩니다.

> **정리하기 전에**: 2단계 인증을 이미 설정했다면 **백업 코드를 먼저 저장**하세요.
> 인증 플러그인을 잘못 건드리면 본인이 못 들어갑니다.

## 4-c단계 · ⚠️ 테스트 도메인에서 작업할 때

카페24 임시주소(`***.mycafe24.com`)에서 만드는 경우, **이건 인터넷에 공개된 주소입니다.**
내 컴퓨터(LocalWP)와 달리 누구나, 검색엔진 로봇도 들어올 수 있습니다.

방치하면 두 가지 문제가 생깁니다.

1. **미완성 페이지가 검색결과에 노출됩니다** — 브랜드 신뢰에 직접적인 타격
2. **나중에 `caparol.kr` 로 옮기면 중복 콘텐츠가 됩니다** —
   같은 내용이 두 주소에 있으면 검색엔진이 어느 쪽을 정본으로 볼지 혼란스러워하고,
   임시주소가 먼저 색인되어 있으면 실도메인의 순위가 눌립니다

### 지금 바로 확인할 것

- [ ] **설정 → 읽기 → "검색 엔진 노출 방지" 체크되어 있는지** ← 최우선
- [ ] `https://주소/robots.txt` 열어서 `Disallow: /` 가 보이는지 확인
- [ ] 구글에서 `site:주소.mycafe24.com` 검색 → 이미 색인된 게 있는지 확인

### 오픈할 때 할 것

- [ ] 실도메인 `caparol.kr` 연결
- [ ] **설정 → 일반**의 워드프레스 주소·사이트 주소를 실도메인으로 변경
- [ ] 임시주소 → 실도메인 **301 리다이렉트**
- [ ] 그 다음에 "검색 엔진 노출 방지" **체크 해제** ⚠️ 순서 중요
- [ ] 네이버·구글에 실도메인으로 사이트맵 제출

> **순서를 지키세요.** 노출 방지를 먼저 풀고 도메인을 나중에 연결하면,
> 임시주소가 색인되어 버립니다. 되돌리는 데 몇 주 걸립니다.

## 5단계 · 보안 (오픈 전 필수)

- [ ] 관리자 아이디를 **`admin` 이외**로 (이미 admin이면 새 관리자 생성 후 삭제)

- [ ] Two Factor: 관리자 계정에 2단계 인증 설정 (**백업 코드 보관 필수**)
- [ ] `wp-config.php`에 파일 편집기 비활성화 추가:
      ```php
      define('DISALLOW_FILE_EDIT', true);
      ```
- [x] ~~XML-RPC 비활성화~~ — `mu-plugins/caparol-core/inc/security.php` 에서 이미 처리됨
- [x] ~~워드프레스 버전 노출 제거, 작성자 아카이브 차단~~ — 동일 파일에서 처리됨
- [ ] 워드프레스 **마이너 버전 자동 업데이트** 활성화
- [ ] SSL 인증서 적용 → HTTP를 HTTPS로 301 전환
- [ ] 직원 계정은 **관리자(Administrator)가 아니라 편집자(Editor)** 권한으로 발급

> 워드프레스의 유일한 진짜 단점이 보안입니다. 여기만 제대로 하면 나머지는 문제없습니다.
